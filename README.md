# 二向箔 / DualVectorFoil

网易《我的世界》基岩版模组，Python 2.7 + nuoyanlib，目标为本机网易 3.10.0.436581。当前版本 **0.1.0**。2026-11-11 已通过 MCDK 验证调色板球形跌落；详细范围见下方验证记录。

## 使用

将 `src/bp`、`src/rp` 作为配套行为包和资源包导入工作台。交付压缩包 `dist/DualVectorFoil-0.1.0.zip` 解压后就是这两个目录，未验证直接导入 ZIP 的工作台行为。

- 创造栏装备分类获取“二向箔”，或使用 `/give @s nuoyan:foil`。
- 合成配方：四角纸、四边玻璃、中心下界之星。
- 右键使用或对方块使用后发射；生存模式消耗一枚，创造模式不消耗。
- 发射后沿准星方向无重力直线飞行，穿透方块，并在配置时长内逐渐减速至静止；默认从出生点继续飞行 12 格，减速耗时 3 秒。
- 完全静止后再等待六秒，以静止位置所在格点为球心获取球形半径内所有非空气方块；默认半径 60 格，不要求连通，球心为空气也会处理周围方块。
- 方块数量由半径决定，不设置总数上限。每维度只允许一枚二向箔飞行、等待或处理；完成后可再次投掷。
- 聊天输入 `!foil` 查看当前维度的平面高度、物体方块数、已处理数量和等待状态。
- 玩家不参与实体二维化，不会被传送、冻结或替换为二维模型。
- 搬移阶段接入局部空间跌落后处理：青金光环、平面网格、空间切片，以及标准档的折射与轻微色散。着色器画面和性能不在本轮调色板实测结论内。

## 命名与目录

- Minecraft 物品、实体、脚本系统及内部持久化标识统一使用命名空间 `nuoyan`；几何体和渲染控制器分别采用 `geometry.nuoyan.*`、`controller.render.nuoyan.*`。
- 模组自有数据文件统一放在项目目录 `dual_vector_foil` 下，例如 `src/bp/entities/dual_vector_foil/`、`src/rp/models/entity/dual_vector_foil/` 和 `src/rp/textures/items/dual_vector_foil/`。
- `manifest.json`、语言表、`textures/item_texture.json` 等必须由引擎从固定路径读取的索引文件仍保留在资源包根目录。

## 已实现的行为

方块采用 **有符号 Morton 3D → 1D → 2D 可逆映射**。原生调色板一次读取区域，直接在调色板字典上筛选球形范围、一次算完二维映射。保留方块名、附加值、状态和含水层；对方块实体额外保存完整 NBT。目标与源调色板按帧批量应用，源/目标重叠通过初始快照及目标索引处理，不再逐格读源或使用分页日志。

非玩家实体采用 **长方体表面展开图 + 排版**：将原模型各 cuboid 的表面切开、展开到 XZ 平面，继续使用原实体贴图。生成了 **196 套几何体、9,222 个零厚度面片**，资源目录覆盖 **125 类原版实体定义**；目录保留的 Steve/Alex 几何不再对玩家应用。这是资源覆盖计数，并非逐类实机通过计数。客户端逐实体替换模型；服务端保存二维化标记、关闭生物 AI 并约束位置。

`FOIL_BLOCKS_PER_TICK = 50` 控制每个服务端 tick 应用的源方块数量，设为 `-1` 后在区块就绪时同次调用全部应用。首次获取与映射同步执行，不受逐帧预算拆分；区块未就绪会等待。调色板计划和分组游标保存在 v3 额外数据中，可重放初始快照恢复进度。

## 当前边界

- 同一维度允许多个二向箔同时飞行、等待和二维化，各任务独立存档与恢复；玩家发射冷却保留。`!foil` 显示当前维度的各活动任务。有限逐帧预算由同维度任务共用；`-1` 仍在区块就绪后全部应用。范围重叠时，各任务按各自捕获的快照推进，后写入的内容生效。
- 每个二向箔的空间跌落特效独立播放一轮，共 5 秒（含淡入与淡出）；播放进度只按本地时间推进，方块处理进度、等待区块、完成消息均不延长或截断播放，同一任务不会重播。多个特效使用独立后处理通道并行播放，结束后关闭并复用通道。
- 地形会被实际搬移，这是模组玩法本身；当前没有撤销功能。
- 实体的**模型厚度是 0**，引擎物理碰撞盒仍是原碰撞盒；第一人称视点、装备附件和个性化皮肤尚未做专门适配。
- 原版船、运输船的几何体没有出现在本机可读取 JSON 中，暂不转换。其他模组实体需提供模型并重新生成目录；未知模型不会用通用方片冒充。
- 原版动态行为仍存在：沙砾下落、液体流动、植物支撑、红石、门/床等多方块关系可能在搬移后变化。不能把“保留状态/NBT”理解为保留所有机械功能。末影箱内容由玩家数据管理。
- 实体上限独立配置，默认不限制；仍只捕获脚底或紧邻支撑方块属于所选球形调色板的非玩家实体。常加载接口不会加载离线区块的生物，实体在其实际进入加载范围后再检测。世界坐标边界、磁盘容量、区块加载和帧预算仍限制推进速度和实际范围。
- 各实体的多个渲染层、装备附件及不同客户端版本需要后续实机核对；当前不宣称所有原版/第三方模型都已兼容。
- 命名空间和持久化键已统一为 `nuoyan`；调色板任务格式为 `v3`，不续跑旧 `v2` 连通扫描和分页任务；旧世界中的方块和非玩家实体标记不由此撤销。
- 空间跌落是颜色/深度后处理，只能限制局部空间，不承担精确方块范围判定；光场内邻近表面也可能被着色。实际编译、画面、RNGL 和性能尚未验证。

## 投掷配置

在 `src/bp/dualvectorfoil_scripts/common/config.py` 中设置。飞行距离和时长必须大于 0：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `FOIL_FALL_RADIUS` | `60` | 球形跌落半径，单位为格，允许 0，不接受负值 |
| `FOIL_BLOCKS_PER_TICK` | `50` | 每 tick 应用数量；`-1` 为区块就绪后即刻全部完成 |
| `FOIL_FLIGHT_DISTANCE` | `12.0` | 从玩家前方 1.5 格的出生点继续飞行的距离，单位为格 |
| `FOIL_FLIGHT_SECONDS` | `3.0` | 沿直线逐渐减速至静止的时长，单位为秒 |

使用原生轨迹运动器的 `out_quad` 减速曲线。轨迹正常完成后固定实际静止位置，再等待 `modules/foil/config.py` 中的 `SETTLE_TICKS = 6 * 30`；默认共约 9 秒后获取球形范围。实体被移除或失效时结束本次投掷，不会提前触发。

## 空间跌落配置

视觉采用维度坍缩：四层悬浮空间切片与断裂光带向二维平面合拢，叠加分层错位、压缩折射、色散和合拢亮峰。已移除圆盘、圆环及向外扩散的圆波；仍按每个二向箔独立播放 5 秒。2026-11-13 本轮只做离线逻辑与源码检查，实际画面与性能待验证。

在 `src/bp/dualvectorfoil_scripts/modules/effect/config.py` 中设置：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `FOIL_FX_QUALITY` | `2` | `0` 关闭，`1` 低配光环/网格/切片，`2` 标准折射/色散 |
| `FOIL_FX_RADIUS` | `24.0` | 坍缩光场范围，限制在 4～24 格，不改变方块处理范围 |
| `FOIL_FX_VIEW_DISTANCE` | `96.0` | 观看距离，末段淡出；完全背向时关闭通道 |
| `FOIL_FX_STRENGTH` | `0.8` | 总强度 0～1，0 关闭通道 |

每个同时播放的特效使用一个后处理 pass，通道按需添加并复用。每个 pass 的源码预算为低配最多 2 次、标准档局部最多 5 次纹理读取；多个特效叠加的开销会增加，未实测帧率。播放到 5 秒或切维度后关闭。详见[空间跌落着色器说明](docs/dev/空间跌落着色器.md)。

`foil` 只负责业务，并通过 `MainServerSystem.BroadcastEvent` 在服务端本地发布 `FoilFieldState`。`EffectServer` 监听流程事件并计算低频视觉快照，跨端通知统一由 `MainServerSystem.NotifyToMultiClients` 发出；`EffectClient` 通过 `server_event` 监听 `MainServerSystem` 的事件并独立负责渲染更新。两个功能模块不互相导入实现；除 Python 2 必需的 `__init__.py` 外，`modules/effect` 保持原有三个职责文件，`modules/foil/palette.py` 独立承担无 SDK 依赖的调色板算法。按用户选择，`EffectClient` 保持无 `Destroy`，退出时交由引擎清理。
