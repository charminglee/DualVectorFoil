# 实现、API 依据与验证边界

## 工作流与来源

本次初始目录为空，未启用 Git。读取一般项目模板，手工追踪：

```text
modMain -> common.constant -> common.project
        -> nuoyanlib.run("nuoyan")
        -> main_server / main_client
        -> modules._base.server / client
        -> modules.effect.server / client
        -> modules.foil.server / client
```

`common/project.py` 只保存项目名、项目目录和命名空间 `nuoyan`，`common/config.py` 保存方块/实体上限和搬移预算。按要求收敛模块文件数：除 `__init__.py` 外，`modules/foil` 与 `modules/effect` 各自只保留 `client.py`、`server.py`、`config.py`。业务辅助实现已合并到对应端侧；`config.py` 保持不导入 ModSDK，离线算法测试通过最小接口替身导入端侧文件。`foil` 负责世界业务与模型替换，`effect` 独立负责视觉同步与局部后处理，功能模块间不互相导入实现。两个功能分别通过 `ClientModule` / `ServerModule` 注册，不修改 nuoyanlib 内部。

用户已明确授权：以本地模板/库源码、网易官方文档和静态依赖检查替代本次缺失的 `scan_py2_mod_architecture`、`scan_py2_import_chain` 及专用 API MCP。这里的检查不冒充这些工具的输出。

| `modules/effect/config.py` | 可调画质、范围、强度、视觉协议、生命周期和预算；不导入 ModSDK |

| `tools/build_geometry.py` | 离线 cuboid 展开、UV 与旧式模型继承、覆盖报告 |

## API/事件核对要点

以下文件名相对于本机 `E:/MCMod/ModSDK/mod`。

| 用途 | 来源 | 已核对的关键语义 |
| --- | --- | --- |
| 发射 | `server/component/projectileCompServer.py`；`E:/MCMod/netease-bedrock-wiki/mconline/100-历史归档教程/60-我的世界创造营教程/SDK大师教程/2-武器和装备制作/3-枪械制作.md` | `CreateProjectileEntity(spawnerId,identifier,param)`；position/direction/power/gravity/damage；失败为 `-1`；自定义抛射物声明 `netease:custom_entity_type=projectile_entity`，同一官方示例以 `minecraft:projectile.gravity=0.0` 实现无重力直线飞行 |
| 物品使用 | `server/serverEvent.py` | `ServerItemTryUseEvent.playerId/cancel`，`ServerItemUseOnEvent.entityId/ret`；两入口共享防重复发射逻辑；同维度门控同时覆盖飞行与处理态，完成态不阻塞下一枚 |
| 命中与 tick | `server/serverEvent.py` | `ProjectileDoHitEffectEvent.id/x/y/z`；事件坐标向下取整为连通扫描首方块；服务端每秒 30 tick |
| 扣除物品 | `server/component/itemCompServer.py` | `GetPlayerItem(CARRIED)`、`GetSelectSlotId()`、`SetInvItemNum(slot,count)`；创建失败不扣物品 |
| 地形 | `server/component/blockInfoCompServer.py` | `GetBlockNew` 只读取已加载区块；`SetBlockNew` 同块同 aux 返回 False，且重复写容器可能清空内容，因此相同状态先跳过 |
| 状态 | `server/component/blockStateCompServer.py` | `GetBlockStates/SetBlockStates` 的维度参数；空字典是合法状态集合 |
| NBT/含水 | `server/component/blockInfoCompServer.py` | `Get/SetBlockEntityData`、`Get/SetLiquidBlock`；更新 NBT 中根级坐标，不假设箱子配对等跨方块逻辑仍成立 |
| 常加载 | `server/component/chunkSourceComp.py` | `SetAddArea` key 必须唯一；位置四周外延 80 格；`CheckChunkState` 判断就绪；`DeleteArea` 释放；常加载不等于 tick，也不自动加载离线实体 |
| 保存 | `server/component/exDataCompServer.py` | `SetExtraData(...,False)` 批量设值后 `SaveExtraData()`；保存失败不得清源 |
| 标记同步 | `server/component/modAttrCompServer.py` | `SetAttr` 服务端自动同步；第三参数是 needRestore，不能当成“是否广播”。实体持久化已由 ExtraData 管理，避免每次扫描重复落盘 |
| AI/重力 | `controlAiCompServer.py`、`gravityCompServer.py` | `SetBlockControlAi(False,True)` 才是冻结；重力 0 意味着采用世界重力，不能用它表示无重力 |
| 实体模型 | `client/component/actorRenderCompClient.py` | 生物 `AddGeometryToOneActor` / `RebuildRenderForOneActor`；玩家使用 `AddPlayerGeometry` / `RebuildPlayerRender`；GetModelStyle 区分普通/纤细/自定义皮肤 |
| 玩家与 AOI | `client/clientEvent.py` | AddEntity 不包含玩家，另监听 AddPlayerCreated、RemovePlayerAOI；轮询当前已加载实体补齐初始化前的 AOI |
| 本地广播 | `server/system/serverSystem.py` | `BroadcastEvent` 调用本端 PostEvent；项目通过 MainServerSystem 发布 FoilFieldState，不产生跨端通知 |
| 事件清理 | `nuoyanlib/core/client/_lib_client.py`、`core/server/_lib_server.py` | 库的 Destroy 遍历注册系统并调用 unlisten_all_events，业务模块沿用自动注销 |

## 已做的离线验证

所有终端命令使用 `pwsh`；没有启动 Minecraft、工作台调试或实机自动化。

- Python **2.7.18** 对 107 个运行时 `.py` 文件编译成功，未执行游戏 API。
- Python 2.7 的 10 项映射/搬移/分页测试通过：35,937 个有符号点往返、极大整数、50 方块批次两次持久化、批次失败续跑、密集连通 343 方块内容保存、目标覆写未来输入、失败重试/重启重放、负坐标分页恢复，以及空气不触发目标区块生成。
- Python 2.7 的 7 项连通物体测试通过：同步单次搜索完成、六面邻接选择、排除非连通对角方块、500,000 上限传递逻辑、未就绪区块原 cursor 重试、脚底支撑格点识别，以及 `MAX_FOIL_ENTITIES = None` 配置。
- Python 3 的 5 项模型测试通过：长方体面积、继承覆盖、零宽原始面片保留、9,222 个生成面片共面/无图表内部重叠、不支持的网格不伪造输出。
- 空间跌落的 12 项状态/协议测试、11 项接口替身测试、3 项系统事件路由测试和 4 项同维度投掷/无重力门控测试通过；与上列 22 项合计 **52 项**。验证本地流程广播、效果模块网络限频、参数写入与主动清理逻辑、发射参数无重力，以及完成态释放后可在同一维度再次投掷，不执行游戏或 shader。
- 后处理配置检查通过：两份原版配置各保留 9 个效果定义和原有顺序，追加一个默认关闭的 pass；三组 vec4 共 12 个参数，材质及 shader 文件引用可定位。
- JSON、独立 manifest UUID、BP→RP 依赖、`nuoyan` 资源标识、`dual_vector_foil` 项目子目录、500,000 方块上限、实体无上限配置、每 tick 50 方块搬移预算、模块注册路径、模型索引与静态业务依赖检查通过。
- `geometry_report.json` 枚举资源覆盖及排除项；`static_report.json` 保存命名空间、项目目录、方块/实体上限、导入图与事件清单。
- 静态依赖检查确认 `foil` 与 `effect` 不互相导入实现，且两端分层没有交叉。旧效果 Python 路径已移除，交付包只包含新位置。

普通解释器测试只能证明算法、文件结构与静态数据满足这些检查，不能证明网易渲染器已成功绘制或网络同步已经实测。

用户明确要求不运行 shader 测试：本次没有 GLSL 编译/链接、离线 GPU 渲染、游戏渲染或性能测试。源码依据、视觉预算与剩余适配边界见[空间跌落着色器](空间跌落着色器.md)。

按用户选择，`EffectClient` 保持无 `Destroy`，退出时交由引擎清理；结束、超时和切维度仍主动关闭效果。未实测退出时的引擎清理行为。
