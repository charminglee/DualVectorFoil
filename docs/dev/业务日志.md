# foil / effect 业务日志

日志前缀为 `[DualVectorFoil][模块.端侧][级别] 事件 ts=时间戳 字段=值`，输出到游戏现有 Python 日志流。`ts` 是 Unix 时间秒数；耗时字段 `duration_ms` 单位为毫秒。按前缀及 `run_id` 可以关联方块处理、视觉同步与客户端生命周期。日志不写额外文件，也不输出完整调色板、NBT 或实体清单。

| 范围 | 主要事件与内容 |
| --- | --- |
| `foil.server` | 初始化与配置、存档恢复、发射拒绝原因、投射物创建/运动/静止/失效、任务创建与结束、区块等待及阶段状态、读取/映射/NBT 耗时、处理进度与保存耗时 |
| `foil.server.world` | 区块窗口申请/失败/释放、局部分区写入耗时、原生接口返回 False 后的读回确认、写入和 NBT 失败的具体坐标、预期与实际数据 |
| `foil.server.entities` | 非玩家实体标记恢复、捕获、持久化失败、约束数量与移除 |
| `foil.client` | 初始化、AOI 进入、模型安装数量、目录缺失/渲染键未就绪/无匹配层、几何安装或重建失败、成功安装与移除 |
| `effect.server` | 初始化、禁用或空任务跳过、观看者加入/离开、发送数量、进度、同步耗时及完成停止包 |
| `effect.client` | 初始化、快照接收/忽略原因、任务开始、淡出/心跳超时、距离方向剔除、摄像机不可用、后处理启停、失败操作、关闭重试及状态清理 |

正常流程使用 INFO，异常配置和接口失败使用 ERROR，可恢复的环境缺失使用 WARNING。每个字段最多输出 512 个字符。日志不会捕获或吞掉业务异常，引擎原有异常堆栈继续输出。

高频进度、批次写入、模型及实体统计每 5 秒记录一次，并通过 `suppressed` 表示期间合并的调用次数；不是丢失方块数或实体数。任务阶段、错误诊断、同步观看者集合变化立即记录；逐帧插值、着色器参数写入成功和单方块成功不逐条输出。日志限频只影响输出，不改变业务 tick、同步节流、游戏预算或重试频率。摘要中的耗时是该次调用耗时，不能当作五秒窗口平均值或 P95。

示例：

```text
[DualVectorFoil][foil.server][ERROR] field_state ts=... count=298838 dimension=0 duration_ms=... error={'reason': 'state_mismatch', 'pos': (...)} moved=0 phase='moving' run_id='...' status='palette_write_failed'
[DualVectorFoil][effect.client][ERROR] postprocess_failed ts=... effect='nuoyan_space_fall' operation='shape' run_id='...'
```

开发验证：`C:/Python27/python.exe -B tests/test_business_logs.py`，再分别执行现有各测试脚本。业务模块引用链由本地源码静态检查确认；缺失的专用 MCP 扫描/检索工具未执行。新增日志没有新增 SDK 接口调用，也没有修改 nuoyanlib。离线测试不代表实机性能或游戏效果验证。
