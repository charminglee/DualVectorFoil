# 天空裂缝着色器（2026-11-13）

本轮按用户确认采用天空后处理：世界方向固定，仅在天空深度像素绘制裂缝，由地形和写入深度的云层遮挡。主裂缝不再创建序列帧粒子；原图集保留作形态参考，不参与新裂缝绘制。

## 时间线与参数

| 客户端秒数 | 行为 |
| --- | --- |
| 0～2 | 青紫边缘的暗色裂口展开 |
| 2～5 | 同一个裂缝开口继续扩大，其边界向外推进直至覆盖全天空 |
| 5～11 | 开口覆盖全天空，内部条纹持续流动，停留 6 秒 |
| 11～13.4 | 开口边界从全天空收回原来的主裂缝 |
| 13.4～15 | 主裂缝两侧向中间靠拢，最终闭合；环境同步恢复 |
| 15 以后 | 关闭通道，恢复原有天空颜色、亮度与覆盖模式 |

原有地面坍缩、折射、碎片及余烬保持五秒动画。天空使用独立的十五秒生命周期，服务端进度和重复心跳不续期。

- `modules/effect/timeline.py`：纯 Python 时间曲线，仅依赖配置，不导入 SDK。
- `modules/effect/playback.py`：触发时捕获中心上方 38 格相对摄像机的世界方向，此后不随摄像机移动重算。摄像机不可用时以向上方向兜底；切维度立即清理。
- `modules/effect/atmosphere.py`：与着色器共用同一退出包络，最后一轮结束恢复之前的覆盖模式。
- `shaders/dual_vector_foil/glsl/sky_rift_v13.fragment`：同一个球面裂口的张开、扩大与合拢；内部条纹通过世界方向上的时间形变及流动亮脉冲持续运动；不采样旧序列帧，不使用天空盒六面贴图。
- 三组 vec4 依次为 `field=(中心 xyz, 有符号半径)`、`shape=(平面 y, 包络强度, 秒数, 展开加扩散进度)`、`style=(固定方向 xyz, 画质开关)`。展开加扩散进度在 0～2 秒从 0 到 1，在 2～5 秒从 1 到 2，保持到 11 秒；11～13.4 秒退回 1，13.4～15 秒降为 0。
- 原有折射、辉光和色散系数固定在 shader 中为 `0.028 / 0.95 / 0.003`；低画质仍跳过折射采样。

本机调试发现：新增第四参数可通过 `GetParameter` 读回，但片元内第四向量输出与自定义方向不符。本轮把数据放回已实测可用的三组 vec4，没有依赖第四组向量。正式资源中不含深度或向量的诊断颜色输出。

## 开口扩张、动态条纹与合拢（v10）

此前的局部裂缝加独立天空裂纹已改为同一个开口。使用起裂方向的球面切向坐标计算开口边界，张开后将横纵角度范围扩大到覆盖整球；内部条纹只在这个开口内显示。展开与闭合都改变真实的开口形状，不靠整幅画面淡入淡出来代替。

条纹的三维形变、沿条纹移动的亮脉冲和青紫颜色流动均由本轮秒数驱动。形变依赖世界方向，保持初始世界朝向。收拢时先缩回全天空开口，再收窄主裂缝；仅在最后 0.4 秒淡掉亚像素细缝。天空边缘亮度与环境的四秒恢复包络分别计算，避免主裂缝在闭合前提前消失。

- 定格实机核对 1.8、3.2、8.0、8.6、13.4、14.2、14.8 秒：开口从竖缝扩大到覆盖画面，背面天空也位于开口内部；条纹位置与亮脉冲随时间变化；最后两侧从张开收窄为细缝。定格仅验证空间形态。
- 测试入口增加 `mcdk_test_sky_sample(age)`；连续播放额外采样 11.8、12.6、13.4、14.2、14.8 秒，`closing_verified` 要求实际 shader 参数递减并进入主裂口闭合阶段。
- 第一组三轮实播中，三轮的停留、收拢和清理均通过，首轮恢复判定误报：覆盖开关已恢复为 False，但原生亮度从约 0.35 变为 1。检查逻辑现按 SDK 的覆盖模式语义判断：原先开启自定义覆盖时比较原值；原先未开启覆盖时核对已交还引擎控制，不要求引擎动态天空读数冻结。
- 本轮仍以本地 SDK、已有依赖链和静态 AST 检查替代专用扫描工具，未调用缺失的 MCP 架构扫描工具；未修改第三方库、foil 业务或世界方块。

本轮证据目录为 `.tmp/sky_rift_motion_20261113/`，包含展开、全天空、条纹流动以及 13.4/14.2/14.8 秒合拢截图与静态验证记录。正常时钟的三轮重测结果另存 `live-results.json`。

最终按修正后的恢复模式检查重新连续实播三轮：`completed=3 / passed=3`，三轮的 `hold_verified`、`closing_verified`、`cleaned`、`restored` 均为 True。另用 `mcdk_test_sky_motion()` 从全展开阶段按真实时钟续播，在约 6～7.4 秒期间连续截图确认条纹形状和亮脉冲实际移动（`motion_live_0.jpg`、`motion_live_1.jpg`）。最终通道关闭、粒子清零、天空与亮度覆盖关闭，测试摄像机锁定已解除，错误日志为空。

## 参考图细化（v13，2026-11-13）

本轮以用户提供的青紫裂缝 4×4 序列参考图为形态目标，继续由程序着色器绘制。主要调整如下：

- 起裂开口改为较宽、较短的尖端轮廓，张开后横向半角约 0.28 弧度、纵向半角约 0.36 弧度；扩展后仍覆盖整片天空，原来的 2/3/6/4 秒时间线保持一致。
- 采用多尺度噪声扰动撕裂边缘，左侧青蓝、右侧紫红；中心保持暗色。冻结退场时的边界形变，保证闭合时边缘向原裂缝中心靠拢。
- 用两级电弧网络、流动的域扰动、局部打断与亮脉冲替换旧的光滑正弦条纹。细分叉及偏白的电弧核心集中在边缘带，外围叠加带噪声的半透明能量层。
- 初次实机细化中，电弧出现大块多边形网格感；后续提高空间密度并打断闭合线条，限制外溢范围。暗色中心、轮廓与外层能量分别控制，避免整个开口变成发亮的实心面。
- 维持一 pass、三组 vec4、五次纹理采样；无新增贴图、发射器、实体或 Python 高频循环。标准画质额外计算细电弧层；低画质跳过该层。着色器新增的噪声计算有 GPU 成本，本次没有做多设备或高分辨率性能测试。

本轮源码静态依赖、JSON、材质路径及范围检查通过，34 项相关离线测试通过。未修改运行时 Python、端侧通信、原版后处理定义、第三方库或工作区既有 foil 改动。
