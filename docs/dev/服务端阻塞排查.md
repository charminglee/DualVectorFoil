# 服务端阻塞排查（2026-11-13）

## 证据与范围

本次只读取既有 MCDK 日志及本地源码，执行离线 Python 2.7 测试，不操作游戏世界，不运行实机回归。专用架构与引用链扫描工具不可用，按项目授权使用本地静态依赖检查。

现有日志反复报告 `modules/foil/client.py` 的 `RuntimeError: dictionary changed size during iteration`。原因是遍历 `applied` 时删除已离开实体；改为键快照遍历，同时避免 `tracked` 在渲染回调中变化破坏迭代。这是确定的客户端错误，不单独用来解释服务端阻塞。

服务端 `_advance_field` 同步捕获、映射、建索引和登记引用，`-1` 允许同次无限量检查及写入。`_save` 还每 90 tick 将包含所有任务快照的 `self.fields` 传给 `SetExtraData`。本地 SDK `E:/MCMod/Tools/ModSDK/mod/server/appmgr/extraDataMgr.py` 的 `SetLevelData` 会同步递归调用 `CheckData`，并非简单赋值，也不等于每次调用都立刻落盘。

离线样本是半径 40 的稠密球体，267,761 方块。本机 Python 2.7 测得：

| 阶段 | 耗时 |
| --- | --- |
| 映射 | 约 0.37 秒 |
| 待搬移引用登记 | 约 0.13 秒 |
| SDK 同款 `CheckData` 校验，三次平均 | 约 0.71 秒/次 |

该测量不包含真实引擎捕获、写块、落盘和渲染，只证明现有同步路径存在明显 CPU 开销。

## 已修改

按用户后续指令，删除方块任务存档入口、启动读取、计划保存门控、定时保存及完成保存。新系统任务字典为空；不再读取旧 `nuoyan:world_v3`，也不续跑退出前未完成的方块任务。未写入世界的内存任务数据退出后丢弃，已经搬动的方块仍属于游戏世界。

用户明确要求保留实体二维化标记，因此 `Attr.FLAT` 的 ExtraData 读写、恢复、ModAttr 同步及实体存活设置均保留。只保留实体标记，不保存方块任务快照。

保留世界写入先目标、再 NBT、最后清源的顺序；没有因移除任务存档删除方块容器的 NBT。
