# 抛射物放射光线

2026-11-13：用户明确要求通过 MCDK 实机验证，本次覆盖此前“先不实机测试”的限制。

## 实现

- `entity/dual_vector_foil/foil_projectile.entity.json` 注册粒子和启动动画；动画在零时刻通过模型 `rays` 定位点启动绑定发射器，停留在末帧，不循环重新创建发射器。
- `particles/dual_vector_foil/foil_projectile_rays.json`：球面向外发射，每秒 90 条、配置上限 96 条，寿命 0.45～0.75 秒；发射周期一秒、无休眠。运动使用世界空间，已发射光线不随实体转动。
- 光束沿速度的 Y 轴展开，白蓝渐变纹理与 `particles_add` 叠加材质增强亮度，不接入全屏后处理。省略环境光照组件，保持光线自身亮度。
- 几何仅添加原点定位点，原有顶点、UV、材质及行为包保持原状。没有改动运行时 Python 业务模块与公共库。

字段依据：[微软动画定义](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/visualreference/actor_animation.v1.8.0?view=minecraft-bedrock-stable)、[粒子面片方向](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/particlesreference/particlecomponents/minecraftparticle_appearance_billboard?view=minecraft-bedrock-stable)、[循环发射器](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/particlesreference/particlecomponents/minecraftemitter_lifetime_looping?view=minecraft-bedrock-stable)，并核对本地 ModSDK `particleSystemCompClient.py`。缺失的专用 MCP 架构扫描、引用链扫描及检索工具未执行，以本地源码、资源引用图和官方文档检查替代。

## MCDK 实测

通过 `execute_code` 创建正式 `nuoyan:foil_projectile` 实体，使用资源动画自动启动粒子；测试入口不创建额外发射器，不把测试实体加入爆发任务，不改动地形。通过引擎轨迹运动三秒平移四格，然后保持静止。截图为实际游戏输出，不是概念图。

| 实体 | 跨循环采样间隔 | 位置跟随 | 清理 |
| --- | --- | --- | --- |
| `-64424509439` | 11.258 秒 | X 从 -81.23549 到 -77.23549 | 销毁实体后，绑定句柄为空 |
| `-64424509438` | 18.747 秒 | 同上 | 销毁实体后，绑定句柄为空；结构化断言通过 |
| `-64424509437` | 19.045 秒 | 同上 | 另测句柄别名，显式移除后销毁实体；结构化断言通过 |

三轮均观察到持续存活、周期年龄变化、移动后停留位置继续工作；多时刻截图确认光束从中心向外放射。第三轮还确认句柄 1 与 125 指向同一效果：移除句柄 1 后，两者的 `Exist` 同时变为 False。因此句柄探测记录不能当成发射器精确计数。

当前引擎内部 `get_particle_num_by_name`、`get_effect_num` 和 `get_total_effect_num` 均抛出 `SystemError: bad format char passed to Py_BuildValue`。最终测试移除这些接口，改用公开组件的 `Exist`、`GetBindingID`、`GetPos`、`GetFacingMode` 和 `GetVariable` 验证。探测范围为 1～1024，不保证覆盖任意长时间运行后的全部句柄，也不声称测量了粒子精确数量。

首版动画显式 `bind_to_actor` 在本客户端解析失败；最终采用定位点和默认实体绑定，重载后正常显示。`lookat_direction` 的实际光束方向不符合放射要求，最终改为 `direction_y`。最终 MCDK 错误日志为空，测试实体已移除，测试摄像机已解锁恢复。鼠标输入曾被另一款前台游戏阻止，没有进行输入级投掷操作；本次验证的是正式实体资源绑定、运动跟随、持续播放和清理，不覆盖完整投掷倒计时、爆发搬移、多玩家或其他设备。

## 复测入口

1. 资源更新后调用 MCDK `reload_game(reload_addons=True)`。
2. 客户端导入 `dualvectorfoil_scripts.tests.projectile_rays_client`，调用 `mcdk_test_rays_view()` 设置摄像机。
3. 服务端导入 `dualvectorfoil_scripts.tests.projectile_rays_server`，调用 `mcdk_test_rays_start()`，保留返回的 `entity`。
4. 客户端调用 `mcdk_test_rays_sample(entity, True)`；服务端调用 `mcdk_test_rays_move()`；等待超过三秒再采样并截图。
5. 服务端调用 `mcdk_test_rays_stop()`；客户端调用 `mcdk_test_rays_sample(entity, expected_active=False)` 和 `mcdk_test_rays_view(True)`。实体另有 45 秒超时销毁兜底。

这些测试函数仅显式调用时运行，不在正式启动路径导入；客户端和服务端分别导入各自入口。离线通过 JSON 解析、资源标识与定位点引用、纹理尺寸/RGBA、配置边界检查及两个测试模块的 Python 2.7 语法检查。
