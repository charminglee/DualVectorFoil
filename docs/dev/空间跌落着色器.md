# 空间跌落着色器：设计、接线与验证范围

目标版本为本机网易基岩版 **3.10.0.420447**。本次新增源区域的青金色空间切片、地面光盘与网格、向二维平面收拢的局部折射和轻微色散。效果图是视觉概念，不能作为实现截图或性能证明。

**用户要求不运行 shader 测试，也不实机测试。** 本次不编译 GLSL、不启动 GPU 渲染、不生成离线渲染截图。下述着色器效果、采样预算与坐标推导来自源码分析；实际编译、引擎加载、坐标方向、画面和帧率均未确认。

## 模块与流程

| 文件 | 职责与引用方 |
| --- | --- |
| `common/constant.py` | 独立注册 `EffectClient` / `EffectServer`；声明公开流程事件 `ServerEvent.FoilFieldState` |
| `modules/foil/server.py` | 把内部业务状态转换为常数大小的公开流程事件，并通过主系统在服务端本地广播 |
| `modules/effect/config.py` | 可调画质、范围、强度、视觉协议、生命周期和预算；不导入 ModSDK |
| `modules/effect/server.py` | 监听服务端本地流程广播，`SpaceFallSync` 筛选附近玩家、限频并发送视觉快照 |
| `modules/effect/client.py` | `SpaceFallState` 视觉插值/剔除、`SpaceFallRenderer` 后处理开关与参数，以及 `EffectClient` tick 和维度清理 |
| `shaders/dual_vector_foil/glsl/space_fall.vertex`、`.fragment` | 单通道全屏后处理源码 |

通信链路为：

```text
FoilServer
  -> MainServerSystem.BroadcastEvent("FoilFieldState", 公开流程状态)
  -> EffectServer.FoilFieldState                         [服务端本地]
  -> NotifyToMultiClients("FoilSpaceFallState", 视觉快照) [必要的跨端同步]
  -> EffectClient.OnSpaceFallState
```

开始搬移、恢复已有搬移和完成时发布流程事件；持续阶段随现有服务端 tick 发布。效果模块自行限制活动网络通知每 10 tick 最多一次，结束通知立即发送。`foil` 不依赖效果画质、shader 参数或同步频率，`effect` 不读取 `foil` 私有字段或世界存档。效果模块在注册列表中位于 `foil` 之前，以接收初始化期间恢复搬移的广播。

本地事件来源为 `nuoyan:MainServerSystem:FoilFieldState`，由 `modules/foil/server.py` 构造。接收方只读使用以下载荷：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `dimension` | int | 目标维度 |
| `phase` | str | `moving` 表示处理持续，`complete` 表示结束 |
| `tick` | int | 发布方的服务端 tick，效果模块据此限频 |
| `origin` | tuple(int, int, int) | 二维输出平面的业务原点 |
| `source` | tuple(int, int, int) 或 None | 当前源方块坐标；空目标为 None |
| `processed_count` | int | 已处理的格点数量 |
| `block_count` | int | 本次连通物体的方块数量 |

位置复制为 tuple，载荷不包含整个方块列表或内部 `state` 引用。效果模块据此生成跨端快照的中心、平面顶面 Y 和进度；这些视觉参数不回流到业务模块。跨端事件的来源为 `nuoyan:MainServerSystem:FoilSpaceFallState`。

只有靠近源区域或输出光盘的同维度玩家接收状态。晚加入或走近的玩家在下次状态更新时加入。离开的观察者收到停止通知；客户端若 2.5 秒收不到更新，也会淡出并关闭。每个客户端只保留一个当前维度的状态。

`EffectClient` 独立监听 `OnScriptTickClient`，不借用 `FoilClient` 的模型检查。使用实际时间计算 0.45 秒淡入和 1.1 秒淡出。很小的目标保留至少 0.65 秒的展开窗口；较近的前沿位置平滑追随，超过两倍半径的跳变重新展开，避免将中间未处理区域扫亮。完成通知保持最后可见中心，余辉不会跳到最后一个远处方块。

按用户明确选择，`EffectClient` 保持无 `Destroy`，退出时交由引擎清理，不恢复业务销毁回调。库负责注销注册系统的事件。结束、超时、切维度或维度变成 `-1` 时仍主动关闭效果。后处理 API 返回失败会记录一次原因并停止该客户端本次会话的效果；关闭接口失败时保留启用状态记录，间隔一秒重试关闭。接口替身测试只能验证调用逻辑，退出时的引擎清理未实测。

## 着色器参数与坐标

`paras` 顺序与三个 vec4 严格对应，总共 12 个 float：

| 参数名 | GLSL | 内容 |
| --- | --- | --- |
| `field` | `EXTRA_VECTOR1` | 平滑后的世界中心 XYZ、展开半径 |
| `shape` | `EXTRA_VECTOR2` | 二维输出方块顶面 Y + 0.02、总强度、循环时间、搬移进度 |
| `style` | `EXTRA_VECTOR3` | 折射幅度、辉光强度、色散幅度、是否启用标准档折射 |

顶点阶段用 `CAMERA_POSITION` 得到中心与平面相对摄像机的位置；利用视图旋转的转置得到世界方向射线。片元阶段按原版 OpenGL 深度约定恢复观察空间深度，再与插值射线相乘。该推导依赖普通透视投影与正交视图旋转，尚未经过网易渲染器验证；特殊相机投影和很远世界坐标的精度属于后续实测范围。

源区域采用局部椭球遮罩，在可见表面上绘制移动切片和扫描纹路。光盘只做一次解析射线/平面求交，与场景深度比较后绘制细环和网格；不进行体积步进。标准档将采样位置朝平面方向偏移，额外检查偏移点深度，减轻前后景边缘串色。近相机深度小于 0.8 的像素直接保留，0.8～1.5 之间渐入。

这不是逐方块的三维动画或连通物体 ID 遮罩：后处理只知道可见颜色和深度，可能影响光场内的邻近表面。真实方块仍按原来的连通扫描与可逆映射搬移，模型仍按原来的二维几何替换。

## 性能预算与配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `FOIL_FX_QUALITY` | `2` | `0` 关闭，`1` 低配，`2` 标准 |
| `FOIL_FX_RADIUS` | `14.0` | 局部视觉半径，运行时限制为 4～24 格 |
| `FOIL_FX_VIEW_DISTANCE` | `64.0` | 中心观看距离；最后 30% 距离逐渐淡出 |
| `FOIL_FX_STRENGTH` | `0.8` | 总强度，范围 0～1；0 直接关闭通道 |

配置位于 `src/bp/dualvectorfoil_scripts/modules/effect/config.py`，重载模组后生效。低配仍是原分辨率，省去折射和色散采样；不会降低整个游戏画面分辨率。

- 新增一个全分辨率 pass，仅可见时启用；低配有效像素最多两次纹理读取，标准档局部折射像素最多五次。这里的次数来自源码，不是 GPU 性能测试。
- 屏幕上不在光场内的像素在颜色和深度读取后直接输出。**局部遮罩不等于局部绘制**：启用期间仍要运行全屏 pass，并承担引擎深度纹理及目标缓冲开销。
- 顶点阶段计算射线，片元阶段没有矩阵求逆、循环光线步进或额外模糊 pass。
- 折射偏移上限约为画面短边 1%，色散每侧偏移上限约为 0.1%，实际再乘强度和局部遮罩。辉光只加在细线，不修改原版 bloom 或全屏曝光。
- 每个客户端最多一个效果，没有额外特效实体和粒子发射器。服务器为每个活动维度每秒约做三次玩家筛选，成本随在线玩家数变化，不随 500,000 方块集合大小增加。
- 本地流程事件随服务端 tick 分发；3 Hz 限制由效果模块施加于跨端活动通知。结束通知立即发送；同 tick 和间隔不足 10 tick 的重复激活通知被合并。

## 资源生成与固定入口

运行 `py -3 tools/build_space_fall.py`，或传入 `--data <目标游戏data目录>`。生成器保留目标版本两份原版后处理 JSON 的原顺序、启用状态和所有 pass，仅追加 `nuoyan_space_fall`，默认关闭。源文件路径与 SHA-256 记录在 `space_fall_sources.json`。

`materials/postprocess.material` 与 `graphics_settings/post_process.json`、`post_process_rngl.json` 是官方示例使用的固定入口，作为项目子目录规则的例外；shader 本体位于 `shaders/dual_vector_foil/glsl/`。材质名使用 `nuoyan_` 前缀，因为材质定义里的冒号是继承语法，不使用 `nuoyan:...` 冒充普通材质名。

固定入口依赖资源包加载顺序，同时覆盖后处理配置的其他资源包需要合并这些入口文件。保留原版配置不代表已经验证其他后处理模组兼容性，也不代表 RNGL 路径已实机通过。

## 本次验证

- 真实 Python 2.7 编译运行时代码。
- 12 项纯状态/协议测试，包含淡入淡出、短任务、可见性、维度、超时、插值、500,000 元素只索引和事件载荷不引用可变世界数据。
- 11 项 Python 接口替身测试，包含启用去重、参数失败关闭、关闭失败延迟重试、控制器清理、画质关闭、玩家筛选、晚加入、效果模块限频与结束通知。
- 3 项系统事件路由测试：无效果监听方时只本地广播；实际系统处理函数的本地到跨端路由；客户端效果入口拥有 tick 和维度回调。上述测试均不执行游戏或 shader。
- `tools/validate.py` 检查 JSON、三组 vec4 参数顺序、单 pass 默认关闭、shader 路径存在、原版配置数据相等和端侧依赖；它不编译或执行 shader。
- 原有映射、连通物体与模型数据测试，以及 ZIP 内容与校验和检查。

**未进行：GLSL 编译/链接、任何离线或游戏内 shader 渲染测试、帧率/显存测试、联网实机测试。** 如后续获准实测，优先核对深度坐标、光盘遮挡、第一/第三人称、低配设备、RNGL、切维度和资源包叠加。
