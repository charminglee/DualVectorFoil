# 三维到二维：研究与实现取舍

检索与实现日期：2026-10-20。这里讨论游戏中的离散映射和模型展开，不把《三体》的虚构物理机制当作现实物理算法。

普通正交投影 `(x,y,z) -> (x,z)` 会把同一竖直柱的方块覆盖到一起。PCA、MDS 或视觉用的嵌入方法也不能直接保证一个方块对应一个独立整数格点。这里需要区分“好看的一张投影图”“体积内所有格点的无重复排布”和“实体表面展开”。

## 方块的确定映射

实现：`src/bp/dualvectorfoil_scripts/modules/foil/server.py` 中的 `flatten` / `unflatten`。

设展开中心为 `o=(ox,oy,oz)`，源方块坐标为 `p`。首先分别对三个相对坐标应用 ZigZag：

```text
Z(n) = 2n                 n >= 0
       -2n - 1           n < 0

M3(a,b,c) = Σ(bit(a,i) * 2^(3i)
           + bit(b,i) * 2^(3i+1)
           + bit(c,i) * 2^(3i+2))

(u,v) = 按偶数位/奇数位拆分 M3(Z(x-ox),Z(y-oy),Z(z-oz))
F(p)  = (ox + Z逆(u), oy, oz + Z逆(v))
```

ZigZag 是整数到非负整数的双射。Morton 编码与按位拆分互为逆过程，因此组合映射在数学整数域上可逆，不会因不同高度而覆盖其他输入的输出。实现只使用 Python 整数，不依赖浮点精度或预设位宽。

这三个性质适合本任务：

1. 输出高度固定为 `oy`。
2. 映射不以扫描进度作为参数，物体后续如何排序都不改变已计算出的输出坐标。
3. 负坐标、世界高度以下的相对偏移都使用同一套规则。

代价是三维邻接关系不能全部保留；地形会被切分和重新排布，不能宣称等距或保角。保留 `N` 个方块就需要 `N` 个输出格点，大区域会占用更多二维面积。Minecraft 的有限坐标范围也不是数学上的无限平面。

## 连通物体与覆盖

`modules/foil/server.py` 中的 `advance_scan` 从二向箔实际命中的第一个非空气方块开始执行迭代式广度优先搜索。只把共享一个完整面（六邻居）的任意非空气方块视为直接相连；空气不继续展开，因此扫描在一层空气边界终止。直接或间接相连的方块组成本次唯一物体，不相连的方块即使位于同一包围盒内也不会处理。实现使用队列而不是 Python 递归，避免调用栈深度限制。

单个二向箔最多记录 `MAX_FOIL_BLOCKS = 500000` 个非空气方块，配置位于 `common/config.py`。达到上限时立即停止发现新方块，并按当前扫描顺序处理已经记录的部分。实体上限 `MAX_FOIL_ENTITIES = None`，即不限制实体数量；但实体仍必须由脚底格点或紧邻支撑格点命中本次连通物体。

连通扫描在命中后同步执行，不设置每 tick 候选数预算；搜索完成后才进入搬移阶段，避免搬走方块时破坏后续连通关系。若搜索遇到未加载区块，则保存队列、已检查位置、物体位置表和 cursor，待该区块就绪后从同一位置继续。进入搬移阶段后，每个服务端 tick 最多处理 `FOIL_BLOCKS_PER_TICK` 个方块，当前配置值为 50。

展开目标可能落在尚未处理的三维区域，必须先保存该位置的原内容。平面日志按 `(dimension, chunkX, chunkZ)` 分页，记录覆盖前的快照。以后轮到这个源格点时，从日志读取原输入；如果它已经承载其他源的二维输出，就不再清除实际方块。这样避免输入/输出别名污染。

搬移按 tick 内的最多 50 个源方块组成批次：先为整批读取源快照和目标原内容，写入分页日志并一次性保存批次；再逐格放置目标及状态/NBT、清除源；整批完成后再次保存搬移游标和计数。失败时保留 batch 与游标，下一 tick 从失败格继续；重复设置相同方块不能简单视为失败，因为网易接口明确会对此返回 `False`。

这是一套可重入的应用层日志，不是引擎数据库事务。`SaveExtraData` 与世界区块落盘的崩溃一致性没有实机证明，不宣称断电情况下绝对原子。

## 实体的表面展开

实现：`tools/build_geometry.py`，在开发阶段生成资源，不在游戏 tick 中解析所有模型。

1. 读取 `models` 下的原版 geometry，兼容 1.8 形式、1.12 形式及旧式继承。
2. 对每个 cuboid 的六个表面生成十字/带状展开图，保留对应 UV；原本为零宽/零高的面片按实际定义的正反面展开。
3. 将各 cuboid 的完整展开图按行排放，既不重叠，也不丢弃内部被遮挡的 cuboid 表面。
4. 输出方片统一 `origin.y=0`、`size.y=0`，不是用很小的正数冒充二维。
5. 保留原骨骼名称的空节点，供原动画查找；所有展开面挂在独立根节点上，避免走路动画把面片抬出平面。
6. 每个面提供共面的上/下表面，原实体纹理仍由原渲染控制器提供。

这相当于多个切开的表面图表共处一个平面，不是把整个实体拓扑保持为一张无缝纸。对于标准 cuboid 表面无需 LSCM 数值求解；对于带 `poly_mesh` / `texture_meshes` 的资源，生成器记录不支持，不生成误导性的替代模型。

当前 196 个几何体生成 9,222 个面片。离线测试验证这些面片严格共面、面积合理且各图表无二维内部重叠；实际双面渲染、材质和装备附件仍需游戏验证。
