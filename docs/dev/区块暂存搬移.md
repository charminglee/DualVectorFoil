# 未加载区块暂存与加载事件补应用

2026-11-12，按用户要求：未加载区块不阻塞当前遍历，不丢弃方块；暂存引用，等待对应服务端区块加载事件后应用。

## 搬移语义

- 初始球形捕获和映射流程保持原逻辑；进入搬移阶段后释放旧的源/目标强加载窗口，不再等待整个源或目标矩形。只检查当前引用实际源和目标格点所在区块。
- 未就绪项保存到任务的 `pending_moves` 字典，以唯一源索引为键，值为 `(方块分组键, 组内偏移)`。快照、状态表、含水层、actor 和完整容器 NBT 仍引用原任务数据，不复制整份调色板。
- 同一批有部分未就绪时，其他已就绪项继续写入。未就绪引用不执行自身的目标写入、NBT 恢复或清源操作；跨项重叠仍按原快照及目标集合保护处理。
- 源或目标任何一侧未加载都暂存；加载事件只唤醒该维度、该区块关联项。实际执行前重新检查两侧，若再次卸载则重新暂存。
- 事件回调立即尝试应用被唤醒引用，与普通调度共享当前任务每 tick 的方块预算，其余就绪项由后续 tick 继续，避免多个加载事件在同一帧集中写入。重复事件不重复计数。只有写入、NBT 和清源均成功，才删除对应暂存项并累计 `moved`；真实写入失败保留引用供重试。
- `move_cursor` 现在表示原始计划已遍历数量；`moved` 才是实际完成数量。正常情况下 `move_cursor = moved + len(pending_moves)`。视觉进度使用 `moved / block_count`，不把暂存当成完成；视觉位置跟随最近成功处理项。`!foil` 和流程日志另列暂存数量。
- 原计划全部遍历但尚有暂存时，任务仍为 moving，状态为 `waiting_chunks`，不误报完成；休眠引用不会每 tick 轮询。所有暂存应用成功后才结束。

## 恢复与限制

暂存引用纳入既有周期存档。恢复时重建运行期反向索引，并把保存的引用放入一次性检查队列，覆盖重载期间已经加载、因而错过加载事件的情况；旧任务从原游标继续。沿用原项目的周期保存与幂等重放规则，不宣称断电事务一致性。

初次捕获仍保留原来的区域准备逻辑；本次取消的是搬移阶段的矩形等待和强加载申请。若某些区块此后始终未自然加载，对应引用会一直暂存，不自动丢弃或强制加载。
